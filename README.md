# Dissertation Lab — UEBA Resilience Against Generative Keystroke Impersonation

Quantitative experimental pipeline for evaluating whether User and Entity Behavior Analytics (UEBA) classifiers used in Zero Trust Policy Engines can distinguish authentic human keystroke dynamics from AI-synthesized impersonation.

## Research question

Can a Policy Engine trained **only on human** keystroke telemetry still reject keystroke samples generated by VAEs and GANs that mimic an authorized user’s typing rhythm?

## Dataset

[CMU Keystroke Dynamics Benchmark](https://www.cs.cmu.edu/~keystroke/) — `DSL-StrongPasswordData.csv`

- 51 subjects × 400 repetitions of a fixed strong password
- Timing features: Hold (`H.*`), Flight / Down-Down (`DD.*`), Up-Down (`UD.*`)

Place the CSV at:

```text
data/raw/DSL-StrongPasswordData.csv
```

Or download:

```bash

  https://www.cs.cmu.edu/~keystroke/DSL-StrongPasswordData.csv
```

## Methodology (four phases)

1. **Data acquisition** — load and validate CMU keystroke CSV
2. **Feature engineering** — Hold Time + Flight Time vectors (configurable)
3. **Policy Engine** — Random Forest / RBF-SVM trained on human enrollments only
4. **Adversarial synthesis** — per-user VAE and WGAN-GP samples reserved strictly for testing

## Evaluation metrics

- **TAR** — fraction of genuine human verification samples accepted
- **FAR (human)** — fraction of other-subject human samples accepted
- **FAR (attack)** — fraction of AI-synthesized impersonation samples accepted
- **EER** — equal-error operating point used as the PE threshold
